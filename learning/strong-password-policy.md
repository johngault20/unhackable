# Strong passwords, passphrases, and account policy

## The practical policy

- Use a different credential for every account.
- Prefer randomly generated passwords stored in a reputable password manager.
- If you must memorize one, use a long passphrase made from unrelated words; do not use a famous quote, personal information, or a predictable template.
- Avoid common passwords, reused passwords, keyboard walks, repeated chunks, dates, and “leet” substitutions of common words.
- Use MFA, especially for email, financial accounts, cloud storage, and your password manager.
- Use a passkey or hardware security key when the provider supports it and it fits your needs.
- Change credentials when there is a reason to believe they were exposed, not merely because a calendar reminder says so.
- Store recovery codes safely and protect the recovery email account.

## Why length helps but is not enough

A longer password can make guessing harder when it is unpredictable. A long phrase based on a famous quote, a repeated word, or personal details can still be guessable. A short random-looking password may also be reused or already exposed. The offline checker looks only for a few visible patterns and length bands; it cannot tell whether a candidate is unique, secret, breached, or accepted securely by a particular service.

## Password managers

A password manager helps generate a different high-entropy password for every site and reduces the need to memorize many credentials. Protect the manager with a strong unique master passphrase and MFA where available. Keep a safe recovery plan; losing access to the manager can be disruptive.

## This is guidance, not a guarantee

Services have different rules and risks. Follow the provider's official requirements, use MFA, and respond promptly through the official app/site if a credential may have been exposed. Do not submit a real password to online strength testers, this repository, or an AI assistant.
